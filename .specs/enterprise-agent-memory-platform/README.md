# 企业级 Agent Memory Platform 产品议题

> 这是独立于 `final-v1` 的产品发现与决策空间。这里记录企业级 Agent Memory Platform 的核心议题、讨论过程和阶段性结论；不与既有 Final V1 的对象模型、页面设计和原型混合。

## 产品核心

```text
外部 Harness 负责执行工作；
Memory Platform 负责保留、理解、治理并复用工作的记忆与知识。
```

平台面向 Codex、Claude Code、DSH、OpenClaw、Hermes 等外部 Harness 接入，同时运行平台自有治理 Agent，将工作过程中的证据沉淀为可追溯、可验证、可进化的企业知识资产。

## 讨论方式

按议题逐项讨论。每个议题独立成文档，记录：

- 问题定义；
- 适用场景与使用者；
- 输入、输出和对象边界；
- 权限、生命周期与审计影响；
- 保留、修改、暂缓或放弃的取舍；
- 已确认结论与仍待讨论的细节。

在核心议题的大方向和边界讨论完成前，不提前编写 PRD 或原型。所有未标记为“已确认”的内容都不是既定需求。

### 原始议题表述

1. **跨 Harness 工作现场连续性**：Codex 切换 Claude Code、DSH 后，继续获取同一个 Project / Code Scenario 的有效上下文。
2. **记忆自动分层**：对话自动整理为 L0 对话、L1 原子、L2 场景、L3 事实。
3. **记忆自动归属**：自动判断内容属于 User、Team、Project 或 Agent 的哪个 MemorySpace。
4. **记忆按需融合**：根据当前 Harness、用户、Team、Project、Task 和代码场景，仅取需要的记忆。
5. **记忆自动知识化**：将记忆转化为 Wiki、Skill、RCA、Template、Code Context 候选。
6. **代码场景和根因分析**：将代码版本、工具调用、失败原因、修复路径和验证结果形成可恢复场景。
7. **企业记忆血缘**：任意 Wiki、Skill、RCA、L3 事实都能回溯到 Harness、用户、对话、工具调用和代码 revision。
8. **使用反馈驱动的自进化**：根据采纳、修改、测试成功、构建失败、人工评价和过期情况，更新、收窄或退休记忆与 Skill。
9. **企业级权限与治理**：Team、Project、User、Agent、MemorySpace、Harness 和资源之间的读取、使用、写入、审核边界。
10. **跨空间复用与脱敏**：Project 经验如何安全提升为 Team 级 Wiki、Skill 或 L3 事实。

### 已确认的跨议题能力骨架

1. **来源、版本与血缘**：记忆、场景、知识、派生资产、导出和副本绑定来源、revision、Purpose、范围、责任边界和证据快照；未知、过期、部分和冲突状态显式保留。
2. **权限与用途门禁**：主体、Team/Project/租户、Harness、目标空间、Purpose、敏感度、血缘、当前策略和工具能力取交集；发布/检索不自动授予执行权，Action 默认阻断。
3. **派生与撤回**：索引、Embedding、Cache、Manifest、Export Asset、备份、离线和 Provider 副本分别治理；撤回先阻断新检索、投影、下载、执行和再分享；外部未知不伪造为已清除。
4. **清理与保留**：采用 Copy Inventory、传播阻断、分层处置、独立验证和证据边界；服务阻断、备份生命周期、法律保全和恢复重建分离；保留不恢复服务可见性。
5. **恢复与一致性**：恢复、重建、迁移、重试和灾备切换产生新观测/副本，必须重新盘点和门禁；采用版本化清理意图、幂等处置、可重入验证、冲突对账和安全关闭。
6. **跨边界报告与通知**：事实内核与受众投影分离；内部、客户、Provider、监管输出按最小必要范围生成；触发、遏制、评估、审批、投递、修订和复盘分离。
7. **外部副本与供应商**：采用 Provider/再处理者责任图、范围绑定证明包、分层审计权和证据不足 fail-closed；能力声明、请求、执行、验证、认证和合同材料不互相冒充。
8. **高影响安全默认值**：无法证明、权限/责任不明、恢复竞态、通知失败、法域冲突、外部副本未知或不可逆动作未获授权时，优先收窄、隔离、阻断和升级。

剩余内容均为实现和责任校准：最终 Schema/API/DSL、数据库/事件协议、算法与阈值、抽样和统计参数、性能与 SLA、组织角色/审批/代理矩阵、Provider 合同与互认、具体法域和通知模板、终端/MDM/DLP/DRM 能力、真实拓扑与攻击/恢复样本。它们已逐项记录依赖和不固化原因，不在缺少真实数据、部署拓扑、责任人或法务决定时自动冻结。

### 进入实现前的最小验证

- 版本化 Inventory 与血缘/撤回闭包的一致性和覆盖盲区；
- 恢复、重建、Provider 回执冲突和外部副本未知下的 fail-closed 行为；
- 多受众报告字段投影、翻译语义、投递/撤回证据和通知版本；
- 权限、Purpose、敏感性、跨租户/跨境和不可逆动作的门禁与审计。

验证结果、真实责任矩阵和法务结论出现后，再分别移交 `bmad-spec`、`bmad-architecture` 或实现工作；本改进循环不执行外部删除、通知、迁移或代码变更。
