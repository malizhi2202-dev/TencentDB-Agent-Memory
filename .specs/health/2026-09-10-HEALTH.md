## 一、🔴 严重（5 项）

### 🔴 S1 · 安全：`/admin/users` 是唯一未套管理守卫的后台路由

**Symptom**：`routes/index.tsx:59` 注册 `{ path: 'admin/users', element: <UserManagementPage /> }`，**没有** `AdminOnlyGuard`；同文件另外 3 条后台路由（`model-config` / `permissions` / `audit-log`）都套了。且 `UserManagementPage.tsx` 页面内部**无角色判定**。

**Consequence**：任何已登录用户直接访问 `#/admin/users` 即可进入全局用户管理页；后端是否二次拦截**未验证**（前端防线缺失已确定）。

**Remedy**：包上 `AdminOnlyGuard`（与另 3 条一致）；同时在 `05-TECH-PLAN.md` 的 `check-invariants` 门禁中加"后台路由必须有守卫"的断言。

## 二、🟡 中等（4 项）

### 🟡 M1 · 同名文件与同名目录并存 → 488 行实现被静默遮蔽

**Symptom**：`pages/admin/UserManagementPage.tsx`（452 行，**被路由解析使用**）与 `pages/admin/UserManagementPage/index.tsx`（488 行，**死代码**）并存。模块解析优先 `.tsx` 文件。死实现使用的 **44 个 `admin.*` i18n 键一个都未定义**。

**Consequence**：排查"文案为何缺失""哪一套在跑"时极易误判。**本次首轮排查即被它误导**（52 个缺键中 44 个来自这个死文件）。

**Remedy**：删目录实现；`check-duplicates` 禁止"同名文件 + 同名目录"并存。

### 🟡 M2 · Workbench 双实现（迁移做了一半）

`pages/WorkbenchPage/`（9 文件）与 `pages/workbench/WorkbenchPage/`（6 文件）**并存**；路由使用新的，而**新的反过来 import 旧目录的组件** → 迁移未收尾。

**Remedy**：合并为一套，删除旧目录（属"两套实现"而非"丢失"）。

### 🟡 M3 · `types.ts` 重复 interface 声明（TS 静默合并 → 类型错位）

`lib/api/types.ts` 中 `Project` 声明于 **68 / 94** 行、`ProjectMember` 于 **84 / 110** 行、`Automation` 于 **198 / 217** 行。

**Source**：TS `interface` 同名会**声明合并**；两处字段集不同时合成一个"谁都不匹配"的类型，编译器**不报错**。

**Consequence**：前后端字段错位在编译期无法发现，只能运行时暴露。

**Remedy**：合并为单一权威声明；`check-duplicates` 加"同文件重复 interface"检查。

### 🟡 M4 · 23 个死模块

含上述 M1 的死实现；另 `components/asset/*` 与 `pages/ResourcePage/components/*` 存在**三对重复**。`pages/ResourcePage` 被多处引用但自身无路由。

**Remedy**：确认归属后清理（组件库移出 `pages/`）；建议单开一个清理 change，不与功能变更混做。
