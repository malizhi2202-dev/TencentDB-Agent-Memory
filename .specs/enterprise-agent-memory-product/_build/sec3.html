3.2 组件职责

组件职责上游依赖失败时的安全默认值
External Harness 执行工作并产生证据、代码 revision、工具调用与外部效果；平台不把 Harness Session 当作工作真源。 企业身份或工作负载身份、短期凭证或租约。 不宣称外部 Harness 可用性、原环境恢复、外部副作用完成或缓存物理清除；unknown ≠ 成功。
Connector Gateway Connector Contract V1 八项能力：Handshake、Event Append、Idempotency + Cursor、Capability Declaration、Resource Reference、Health / Lease、Probe、Structured Result。 协议与能力协商、实例身份、资源引用、租约。 身份无法验证、能力未声明、租约过期或撤销状态未知时拒绝接纳；未探测 ≠ 可用，assessment.valid ≠ execution.eligible。
Ingestion & Triage 去重、脱敏、归属候选与分诊；区分 Identity / Provenance / Binding / Temporal State 四个独立判断面。 Connector 的幂等事件与 Cursor、来源 ACL、敏感性分类。 权限检查、归属解析、敏感性判断、审计记录、撤回传播或目标 scope 访问验证失败时默认拒绝写入或隔离；缺失或不可信元数据永不扩大 Scope。
Memory Spaces User / Team / Project / Agent 四类并列归属边界；承载记忆的版本、敏感性、生命周期与写策略。 Triage 产出的 canonical_owner_scope 与目标写入授权。 归属未定时保留较窄边界或 ownership_pending；不 fallback 到 Team、最近 Project、个人空间或全局检索。
Knowledge Pipeline Wiki、Skill、RCA、Template、Code Context 五类对象的候选识别、证据补齐、审核与发布。 已确认记忆、Work Thread、代码 revision、审核责任矩阵。 预检失败默认隔离、补证、退回或拒绝，不是「带警告继续」；审核超时保持 Review 或暂停，不自动批准。
Lineage & Evidence 不可变对象版本、类型化关系、运行事件与派生状态的可追溯体系；支持来源闭包与影响闭包。 对象版本、关系断言、运行与验证事件。 血缘缺失或不可信时低风险暂存为不可执行候选、高风险隔离或阻断；影响分析失败返回 unknown / partial，不返回「无影响」。
Policy Plane 主体—资源—动作—用途—作用域—条件—风险—当前状态的授权判定；授权决策与实际执行分离。 主体与委托链、资源 ACL、Purpose、敏感性、保留与保全状态。 硬拒绝优先，下游只能进一步收紧，unknown 不转换成允许；策略或审计系统不可用时高风险路径 fail-closed。
Visibility Context 把主体、委托、源/目标空间、Purpose、ACL、敏感性、revision、环境与策略版本固化为一次可审计的可见上下文。 Policy Plane 与 Lineage & Evidence。 缺少主体、用途、ACL、敏感性、血缘或当前策略时使用最小投影或 fail-closed；未声明用途、深度与范围时不推断最大权限。
Retrieval Plane 关键词、向量、代码邻近、关系与血缘四通道候选发现；通道只加速候选，不授予权限。 已授权 scope 集合、四类派生索引。 索引或过滤环节失败时不退化为全局不受控召回，默认收窄或拒绝；Eligibility = false 不能被 Utility 翻转为可用。
Action Proposal 把建议表达为默认不可执行的声明性对象：目标、来源资产、建议动作、参数摘要、影响预览、前置条件与不适用范围。 检索结果、Purpose、目标 scope、当前上下文。 默认 blocked；需通过当前 RunGate 才能进入 Run。approval ≠ current plan valid。
RunGate + Tool Policy Tool Policy 声明工具能力硬边界；RunGate 针对当前主体、目标、资产版本、风险、审批与能力做动态准入与持续重检。 当前主体与委托链、审批、目标 revision 与环境、Tool Capability Profile。 任一条件缺失、冲突、过期或 unknown 时为 blocked 或人工审核，不得默认低风险；RunGate 不得放宽 Tool Policy。
Constrained Run 按版本化 Run Plan 执行受约束动作，记录实际 Tool Call、计划外差异、停止条件与补偿路径。 RunGate 准入、Run Plan 版本、Tool Policy。 权限撤回时新调用立即阻断并逐 Attempt 重检；结果未知时冻结重复副作用并外部对账，unknown result ≠ safe to retry。
Verification + External Effect 独立验证结果、实际影响范围、残余风险与是否需要回滚；区分执行、验证与外部效果。 实际 Tool Call 与差异记录、验证计划与证据。 executed ≠ verified；无法证明外部效果时标记 unknown，不宣称完成，也不自动扩大副作用。
Copy Inventory 缓存、索引、Embedding、Manifest、导出、备份、Provider 与终端副本的版本化清单、分层处置与独立验证。 权威撤回版本、副本发现观测、责任边界与合同/保全状态。 未发现、不可访问或未接入的副本不能默认为不存在；覆盖率以分层分母与盲区报告，不以单一百分比代表全量。
Notification & Reports 事实内核 → 授权投影 → 渠道 Delivery Intent；支持修订、撤回与投递证据。 事实内核与证据、受众与用途、投递渠道能力。 投影先于渲染，模板不能自行决定权限；unknown、retained、not_scoped、external_copy 必须保持语义；渠道接受不等于送达。

3.3 数据模型（按域）

下表是概念对象与语义边界，不是最终数据库 Schema。字段名取自议题文档中的最小字段集表述；最终字段名、必填性、嵌套、索引与迁移在各议题中均记为暂缓，不在此冻结。

身份与组织域

实体关键字段关系与边界
User user_id、principal_type、memberships、status 通过 TeamMember / ProjectMember 关系加入；身份认证与组织成员关系分离；createdBy ≠ owner ≠ actor。
Team team_id、members、default_policy、lifecycle_state 管理 Team scope 共享资源与默认规则。待确认 Team↔Project 基数存在两种口径：.specs/final-v1/DOMAIN-MODEL.md §3.1 记为「Team → Project 是一对多归属关系，每个 Project 必须且只能有一个 owning Team」；.specs/redesign-v3/DOMAIN-MODEL-AND-IA.md §3.1 记为「Team ↔ Project：多对多协作关联」，且 §2 明确「Team 不是 Project 的父目录」。两处口径冲突，本文件不自行裁决。
Project project_id、owning_team_id、visibility（open / restricted）、members / ACL 具体工作现场，组织 Task 与 Project scope 资源；Project 可比 Team 默认规则更严格，不能放宽或绕过上级限制。基数口径同上。
Agent agent_id、version、visibility、owner、view / use / write grant、status 关联 Team / Project 只授予明确的 view / use 能力；不自动获得写入、工具或审批权；Agent proposal ≠ approval / publish。
Harness harness_id、instance_id、capability_profile、credential_reference、lease_id、revoked_at 能力声明不等于当前授权；身份分 Logical / Deployment / Instance / Credential 与工作负载证明；撤销分凭证、实例、部署、单项能力、组织或租户。
MemorySpace space_id、space_type（user / team / project / agent）、canonical_owner_ref、lifecycle_state、sensitivity、current_revision 四类并列，不采用单一树形；不提供 public Memory；belongs_to / participates_in / references 不自动继承 owner、读取权或发布权。
Delegation delegator、delegate、resource_scope、allowed_actions、expires_at、allow_subdelegation、revocable delegate_effective_permission ⊆ delegator_effective_permission；默认禁止无限再委托；代理责任链必须记录发起用户、委托 Agent、执行 Harness、审批者与验证者。

工作对象域

实体关键字段关系与边界
WorkThread work_thread_id、canonical_owner_scope、work_status、responsibility_state、current_revision 跨执行者持续存在的工作主体。Work Thread ≠ Chat Session / Harness Session / Run / Checkpoint；认领只改变 active executor。
Task / Work Phase task_id、acceptance_criteria、phase_state、deliverables 可验收目标与阶段。Run succeeded ≠ Task accepted；Phase 完成 ≠ Work Thread 完成。
Execution / Run execution_id、run_id、harness_id、agent_id、result、external_effect Run 是外部 Harness 的执行容器，「不是平台的工作真源」；失败重试创建新 Run。
Attempt attempt_id、goal、action、input_context、result、evidence_refs、next_decision 一次实际推进尝试；失败路径是一等数据，恢复视图应明确已排除路径。
Checkpoint checkpoint_id、created_at、superseded_by 某个时间点的可恢复检查点。Checkpoint ≠ 长期记忆、Checkpoint ≠ Run Context Snapshot；Checkpoint exists ≠ can restore old rights。
CodeScenario scenario_id、code_anchor（repository / revision）、scope、paths、rca_refs、verification_refs、status repo + revision 是共同硬锚点；缺少时不得发布为稳定 Code Context、确定性 RCA、可执行 Patch 或 Skill；branch 是可移动引用，不能替代稳定 revision。
Evidence evidence_id、type、content / reference、observed_at、source_revision、supports / contradicts、sensitivity 追加式保存，只追加不覆盖；事实与推断分开，抽取器不能把模型推断写回成 observed fact。
ContextBinding primaryProjectId、referenceProjectIds[]、writeTargetSpaceId 每个参考项目单独授权只读；读取权限不等于写入权限；显式无权目标直接拒绝，绑定冲突返回 context_conflict。
ContinuationPackage package_version、source_revision、projection_target、gaps、minimum_safe_action 面向下一执行者的续办投影，是可重建的派生物；凭据、Token、私钥与登录态不得进入正文，只记录 credential_ref。
RunContextSnapshot snapshot_id、manifest_id、resolved_at 某次 Run 实际获得的不可变上下文，不热更新；只证明过去发生过什么，不授予当前访问权、发布权或执行权。

记忆与知识域

实体关键字段关系与边界
MemoryItem memory_id、canonical_owner_scope、related_scopes、sensitivity、lifecycle、current_revision_ref 每条可治理记忆只有一个规范归属；归属只表达规范责任与语义边界，不等于权限。待确认 分层口径存在两种表述：议题 02（_facts/01-02-digest.md）记为「L1 = 原子记忆、L2 = 可恢复场景边界、L3 = 长期记忆演进规则」，并明确该文件未定义 L0、未使用「L3 事实」表述；.specs/enterprise-agent-memory-platform/README.md 与 _build/CONTRACT.md 统一演示数据集使用「L0 对话 / L1 原子 / L2 场景 / L3 事实」。两处口径冲突，不自行裁决。
MemoryRevision revision_id、immutable content、parent_revision、evidence_refs、schema_version、content_integrity 不可变内容与状态版本；纠正用追加式 correction_record，不覆盖原归属事实。
MemoryEvent event_id、memory_revision、event_type、occurred_at、actor / producer、idempotency_key、causation_id、policy_context 追加式事实；迟到、乱序或重复事件必须隔离、幂等或生成校正候选，不得以到达顺序覆盖较新有效版本。
KnowledgeAsset asset_id、asset_kind、source_refs、target_space、effective_scope、status、lineage_run 五类对象各有不可替代的回答与消费者：Wiki ≠ Skill、RCA ≠ 普通 Wiki、Template ≠ 历史产物复制品、Code Context ≠ 单纯代码索引、Skill ≠ Prompt 收藏。
KnowledgeAssetVersion asset_version、source_memory_versions、source_work_thread_versions、source_code_revisions、source_policy_version、source_redaction_version、valid_from / valid_until 已发布版本不原地覆盖；派生资产权限不得宽于来源，且 target_scope ⊆ effective_scope。
ChangeSet changeset_id、target_object、mergedHash、headRevision、review_state、publication_state 内容变更、合并、审核与发布对象，不与 RunGate 混称为 Approval。待确认 知识化链路是否以 ChangeSet 为统一变更对象存在两种口径：议题 05 与议题 06 的蒸馏稿明确「两份文档均未出现 ChangeSet 作为知识对象或变更对象」，其链路为 Knowledge Candidate → Review → Publish；.specs/final-v1/DOMAIN-MODEL.md §2 与 .specs/redesign-v3/DOMAIN-MODEL-AND-IA.md §2、§6 定义 ChangeSet 为内容审核发布的唯一入口。不自行裁决。
ProcedureTemplate template_id、kind（scene / playbook）、variables / slots、constraints、verification_rules、locked_version 引用必须锁定版本，升级、复制或派生是显式变更；不创建第二套运行时或独立编排引擎。
ConsumerProjection reference_status、retrieval_status、action_status 三级适配 discoverable → referenceable → actionable；published ≠ actionable，投影必须指向同一资产版本且不扩大原始权限。
FeedbackEvent feedback_id、feedback_type、asset_id / asset_version、context_manifest_id、run_id、repository / revision、authorization_state、anomaly_state 追加证据，不能直接改写资产；反馈不能自动改变 ACL、canonical owner、敏感性、跨空间范围、Tool Policy 或 RunGate。

安全与副本域

实体关键字段关系与边界
Purpose purpose_id、allowed_actions、policy_version 用途决定「能不能使用」，相关性只决定「值不值得优先使用」；相关性不能越过权限。
VisibilityContext subject / delegated_by、purpose / consumer、tenant / project / space、source ACL / target policy、sensitivity、asset state / revocation state、requested depth / expiry、policy_version 不可变、带版本；过滤优先于召回，「不能先全库召回再在最后隐藏内容」。
ContextManifest manifest_id、memory_id、source_revision、owner_scope、inclusion_reason、authorization_context、policy_version、sensitivity_decision、redaction_state 当前授权的一次投影，不是权限本身；必须原子发布，旧 Manifest 只作历史审计，不得继续用于新的检索、注入或行动。
ToolPolicy tool_type、resource_scope、parameter limits、network / file / environment constraints、prohibitions、audit requirements 能力与约束声明，不是某一次执行的批准；RunGate 不得放宽 Tool Policy。
RunGate run_id、subject / delegation、target revision / environment、risk_level、approval_ref、decision（admit / hold / deny） 动态准入与持续重检，不由 Knowledge Asset、Agent 或普通业务代码直接绕过；approval exists ≠ current plan valid。
ActionProposal proposal_id / version、target、suggested action、impact preview、preconditions、not_applicable 默认不可执行；建议不等于执行，Tool Policy 是硬边界。
CopyInventory copy_identity / source_revision、boundary / owner / controller / provider / recipient、purpose / classification / retention_hold、lifecycle / access / disposition、observation / coverage / freshness、proof_snapshot / claim_scope 快照是清理证明的范围基线；内部全量不等于普通用户可见；每个观测、处置和验证保留自己的时间、版本与来源。
ExportAsset export_id / version、requester / approver / recipient、scope / depth、sensitivity、expires_at / revoked_at、integrity digest、reshare policy 独立受控资产；export success ≠ recipient may reshare；revoked ≠ 外部设备已删除。
EvidenceEvent event_id、event_type、observed_at、subject / harness / agent / purpose、source_asset / source_revision / target_scope、sensitivity / policy_version / lineage_ref、operation / result / external_effect、evidence_ref / coverage / freshness、unknown_reason / responsibility / supersedes 清理、报告、投递和补救都引用 EvidenceEvent 与版本化 snapshot；不用一个实时布尔字段覆盖历史事实。
LineageRelation source_object_id / version、target_object_id / version、relation_type、authorization_context、valid_time、status 至少 13 种关系（captured_from、derived_from、supports、contradicts、verified_by、applies_to、projected_to、used_by、invalidated_by、supersedes、revoked_by 等）；derived_from ≠ verified_by；血缘不扩大权限，也不得成为绕过 ACL 的反向索引。
AuditRecord event_id、principal / delegation、purpose / resource_scope、policy_version / decision / reason、plan / run / trace refs、retention_class / legal_hold、event_digest 五类分层追加式证据（Decision / Execution / Impact / Identity-Policy / Lineage-Retention）；retained ≠ retrievable，审计不静默修改。

3.4 技术栈

层选型理由
交付形态本地单文件 HTML 原型（lang="zh-CN"，UTF-8，浏览器直接打开）对应 AC-8：离线可检查、零外部请求，可快速验证信息架构与状态模型。
前端原生 HTML + CSS + JavaScript，无构建依赖满足离线检查与快速验证；不引入 UI 框架依赖。
后端无；合成数据本轮不引入真实服务端，避免把未确定的契约固化。
数据无持久化原型只展示对象与状态语义，不承担存储实现。
部署本地文件或静态服务器不进入生产实现。
关键依赖现代浏览器；Node.js --check（脚本静态检查）零外部依赖前提下完成脚本语法检查。
