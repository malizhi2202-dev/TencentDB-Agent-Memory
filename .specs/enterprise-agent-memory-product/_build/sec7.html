7.2 读这张表的三个前提

前提说明
矩阵是上限，不是授予格子里的 ● 表示「该角色可能拥有此能力」，实际能否操作还要过资源 ACL、Purpose、敏感性、当前策略与 RunGate。矩阵从不直接授予权限。
「可见」也受最小投影约束○ 表示可以看到入口或摘要，不代表能看到全部字段、名称或数量。无权对象一律不披露其存在、名称与总数。
平台管理员不是超级用户platform-admin 只维护公共 Wiki / Skill / Template 与公共模型配置，不能越过 Team / Project 策略直接读取私有内容，也不能代替治理角色审批。

7.3 职责分离（SoD）硬约束

  • 提者不批：提出 ChangeSet 或 Action Proposal 的主体，不能同时是最终批准者。
  • 审批绑定计划版本：审批对象是某一份不可变的计划版本；计划变更即失效，需重新审批。
  • RunGate 独立复核：RunGate 不等于审批的重复，它按当前时刻的主体、目标、Purpose、资产版本与撤销状态重新判定。
  • 清理与报告分离：执行处置的角色与出具验证报告的角色不重合；审计 / 法务只能查看，不能修改事实或自动批准删除。
  • Break-Glass 有边界：紧急通道的每一次使用都留痕、限时、事后复核，不能作为常规放行路径。
