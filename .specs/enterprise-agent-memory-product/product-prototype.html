Enterprise Agent Memory Platform · Product Design

让工作记忆可交接、可追溯、可治理、可撤回

外部 Harness 负责执行工作；Memory Platform 负责保留、理解、授权、复用、撤回、验证并审计工作证据。本文件把已整理的十项产品议题展开为概念模型、流程、架构图、状态约束和可操作界面原型。

1. 产品概念模型

产品不是泛化资源库，也不是新的 Agent Harness。它是连接 Harness、工作现场、MemorySpace、知识资产、权限策略、血缘证据和外部副本的治理平台。

执行与工作

Harness 外部执行环境；WorkContext 可交接上下文；Task 可验收目标；Run 一次执行尝试；CodeScenario 可恢复代码场景。

记忆与知识

MemorySpace 分 User/Team/Project/Agent；MemoryItem 记忆候选；KnowledgeAsset Wiki/Skill/RCA/Template/Code Context；ChangeSet 变更候选。

治理与证据

Purpose 用途；VisibilityContext 可见上下文；ContextManifest 实际使用清单；CopyInventory 副本清单；RunGate 当前准入。

概念职责关键字段/关系不可推导的权限
User / Team / Project身份、组织和工作边界ownership、membership、scope、ACL成员身份不自动授予资源 CRUD
Agent / Harness可版本化的执行配置和外部运行环境binding、capability、lease、policy关联不自动授予管理权或执行权
Memory / Knowledge保存事实、场景、方法和候选资产source revision、lineage、sensitivity、lifecycle发布/检索不自动授予 Action 权
CopyInventory / ExportAsset追踪派生、备份、导出和外部副本copy identity、boundary、evidence、freshness平台看到请求不等于外部已删除

2. 核心不变量

所有权与可见性分离

owner ≠ visibility ≠ ACL ≠ execution authority
membership ≠ resource CRUD
published ≠ actionable
retrieved ≠ approved

证据状态不可夸大

requested ≠ executed ≠ verified
retained ≠ service-visible
unknown ≠ zero
channel accepted ≠ read ≠ deleted

恢复产生新事实

restore / rebuild / migrate / retry
→ new observation / revision / copy
→ re-inventory + re-gate + re-verify

安全默认值

missing / stale / conflict / unknown
→ narrow / isolate / block / escalate
not auto-approve
高风险原则：技术阻断先于法务判断；外部副本无法证明时停止高敏复用、导出和“全量已清理”声明；补偿、回滚、重试和替代 Provider 都是新的受授权动作。

4. 权限、Purpose 与 RunGate

判定层回答的问题失败时
VisibilityContext这个主体在当前 Purpose、空间、revision 下能看什么？过滤候选/投影；unknown 不解释成不存在
ToolPolicy这个工具能力允许什么资源、参数和副作用？硬阻断，RunGate 不能放宽
RunGate这一次具体 Action 现在能否执行？blocked、过期或人工审批
Verification命令结果、实际资源变化和业务结果是否一致？冻结扩大副作用、对账、升级

5. Copy Inventory 与清理闭包

对象清单

源 revision、Cache、Index、Embedding、ContextManifest、导出、备份、灾备、Provider、终端和再分享副本。

证据分层

requested、executed、verified、retained、unknown 各自绑定范围和时间。

报告边界

在线可控范围已验证、备份待生命周期到期、第三方回执未独立验证、外部未知必须分别声明。

6. EvidenceEvent 与状态机

EvidenceEvent {
  event_id, event_type, observed_at,
  subject, harness, agent, purpose,
  source_asset, source_revision, target_scope,
  sensitivity, policy_version, lineage_ref,
  operation, result, external_effect,
  evidence_ref, coverage, freshness,
  unknown_reason, responsibility, supersedes
}

Triage: candidate → staged → assigned | rejected | conflict
Knowledge: candidate → reviewed → published → withdrawn | superseded
Copy: not_scoped → requested → blocked|executed → verified|partial|unknown|retained
Delivery: draft → approved → attempted → accepted → delivered → acknowledged
RunGate: proposed → blocked|approved → executing → verified|unknown|reconciled
状态用户看到什么不能替代什么
verified指定范围、快照和验证时间不能替代其他副本证明
retained保留依据、范围、复核/到期条件不能恢复服务可见性
unknown未知原因、责任边界、下一步不能显示为 0 或成功
blocked阻断原因、所缺门槛、责任人不能通过 UI 强行执行

10. 可交互界面原型

下面不是空白占位页，而是基于上述概念和状态设计的可操作演示。左侧目录已逐页列出原型页面；先阅读页面说明，再在下方切换对应工作台。页面内数据均标记为 SAMPLE，不连接后端。

10.1 工作台 Home

回答：现在需要我处理什么？

汇总当前 Team/Project scope、待分流、待审核、清理 unknown、RunGate blocked 和最近证据。它是治理入口，不是可直接执行高风险动作的控制台。

重点看：当前 Purpose、revision、状态数量、阻断原因和下一门槛。

10.2 Project / Task / Run

回答：当前工作现场和证据是什么？

沿 Project → Task → Run 下钻，查看 owning Team、source revision、验收进度、ContextManifest、Harness 和工具结果；Run 不作为常规顶层资源。

重点看：任务目标、证据完整性、运行结果与外部效果不可混同。

10.3 Memory Triage

回答：候选记忆归谁、能否写入哪个 scope？

展示候选来源、归属理由、置信度、敏感级别、脱敏预览、血缘和目标空间。低置信度、冲突或缺少写权限时，不自动写入更宽的 Team Memory。

重点看：candidate → staged → assigned/rejected/conflict 的分流门槛。

10.4 Agent / RunGate

回答：Agent 能看什么、使用什么、执行什么？

分别显示 view/use/write、关联 scope、Purpose、Tool Policy、Vault reference、RunGate 状态和阻断原因。Agent 关联不自动获得管理权或执行权，秘密只显示引用和指纹。

重点看：Tool Policy 是硬边界，RunGate 只能收紧，不能放宽。

10.5 清理证据

回答：撤回和删除是否真的完成？

沿 Copy Inventory 查看在线缓存、索引、Embedding、Manifest、备份、Provider、导出和终端副本的处置与验证。requested、executed、verified、retained、unknown 必须分开显示。

重点看：unknown 不等于 0；外部副本无法证明时，阻断高敏复用、导出和“全量已清理”声明。

10.6 报告中心

回答：不同受众能看到哪份事实？

先从事实快照生成按内部、客户、Provider 或监管受众的字段投影，再进入批准、投递、确认和修订流程。报告版本、有效期、supersedes/revokes 与 delivery_unknown 都可追踪。

重点看：模板不能绕过字段投影；accepted 不等于 delivered、acknowledged 或 deleted。

11. 原型验收路径

UAT-01 · 工作现场

工作台 → Project → Task/Run：确认 scope、revision、验收进度和证据完整性；Run 只从 Task 下钻。

UAT-02 · Triage

打开候选导入：确认能看到归属理由、置信度、敏感性、血缘和目标；低置信度不得自动写入 Team。

UAT-03 · RunGate

打开 Agent：确认 view/use/write 分离，ToolPolicy 是硬边界，Action 缺门槛时为 blocked。

UAT-04 · 清理与报告

打开 Cleanup / Reports：确认 retained、unknown、verified、delivery_unknown、supersedes 和投影范围不会被合并。

UAT-05 · 安全

使用原型按钮：确认真实删除、迁移、通知、执行均不发生；Vault 只显示 reference。

UAT-06 · 无障碍/响应式

键盘访问、focus-visible、暗色切换、窄屏单列、局部表格滚动和 reduced motion。

实现前最小验证：低敏 CopyInventory/血缘闭包；恢复/Provider 冲突 fail-closed；多受众字段投影/翻译/投递版本；权限、Purpose、敏感性、跨租户和不可逆动作审计。
