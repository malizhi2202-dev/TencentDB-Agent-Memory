## UI 本轮变化

- 重组为五组导航：工作、执行协作、知识与记忆、治理与版本、组织与平台；登录使用独立页面。
- 工作台重排为行动入口、任务与审批队列、上下文说明及知识审查收件箱；保留项目、任务、Agent、Run 的原有专业入口和子页。
- Team/Resources 聚合项目、任务、记忆、记忆空间、Wiki、Code、Skill，并用 Team、Project、Agent、个人四个下拉多选组合筛选；不再单设资产表。
- 将来源记忆自动归纳与 Team/Project/Agent/个人归属放入治理流程，不能判断的进入人工队列；Code 仓库、上传、代码树、图谱、调用链和问答合并为一个工作台。
- Team 是唯一组织入口，Team/Project 独立多对多；平台设置只管理用户、API Key、模型与集成，不再包含登录。

## 推荐体验路径

### 1. 身份和 Harness 上下文

1. 顶栏“登录”进入独立登录页：账号 `demo-lin`，**假密码** `demo-lin-pass`。
2. 登录后从“治理与版本 → 记忆归属”检查自动归纳和待人工处理项；平台集成仍在“平台设置 → 集成设置”。
3. 服务凭据范围只有 `p-db`；独立用户权限取交集。显式越权直接拒绝，不回退；未给 Task/项目的 monorepo 需要确认。
4. 确认绑定后在“会话绑定”查看隔离的主项目、参考读取项目与写目标；候选装配不等于已经注入正文。

### 2. 来源记忆 → 质量 → 经验候选

1. “记忆接收与质量 → 接收与归类”：查看或编辑合成 JSON，校验后接入。
2. 重复接入同一批次，累计调用分母不会膨胀。仅摘要、未知结果、策略拒绝、冲突 ID、派生/注入来源分别处理。
3. “来源记忆质量”：查看样本内 Tool/MCP/Skill 统计、相同错误重试及正常有界轮询的区别，下探原文。
4. “优秀调用经验”：查看归类/空间建议，或把具有成功输入输出证据的样本提出为 Wiki、代码 patch、Skill、Scene、Playbook、经验记忆候选。点击审查链接继续，不自动发布。

### 3. 人工编辑 + 自动提炼 + 并发审查

1. 从 Wiki/Code/Skill 的编辑入口，或“知识变更中心 → 变更队列”保存 ChangeSet。
2. 比较 Base / Current / Proposed；填写合并内容、独立审批人和理由。林晓不能批准自己的人工提案，提炼 Agent 不能自批。
3. 批准并准备依赖后，点击“模拟另一编辑者发布”，再尝试 CAS 发布：旧审批被拒绝。
4. 重新比较、建议合并、重基线、复核并批准；准备依赖后才可发布。受保护人工事实不能静默覆盖。
5. 代码候选的发布仅表示形成已审 patch 提案，不代表修改 Git commit、运行测试或合并代码。

### 4. 版本不漂移

1. 发布前后查看 `t-104` 和 `run-83` 的固定 manifest：旧引用不会被 latest 替代。
2. “版本快照 → 显式升级”填写理由并确认，建立新的 attempt；旧 Run 保留旧版本。
3. 模拟撤销 Wiki 读取权：即使有历史快照，来源读取也被阻断；恢复授权不自动重启暂停的执行。

## 演示边界

这是**需求设计和 UI 交互实现**，不是业务后台实现。没有真实身份服务、数据库、模型调用、仓库解析、向量生成或分布式事务。创建、审批、发布、撤销、统计与审计都在当前页面内存里，**整页刷新恢复初始样本**；只有明暗主题可保存在浏览器本地。角色切换不能证明生产鉴权安全。

状态菜单可体验加载、空数据、失败、拒绝、部分失败、离线与过期；实际走查范围见 [VALIDATION.md](./VALIDATION.md)。更完整的生产目标仍以文档规格为准，不以静态样本冒充后台能力。
